# Портфолио

Персональный сайт-портфолио продуктового дизайнера. Свёрстан по макету Figma
(файл `Auth Center`).

Сейчас готова **главная страница**: первый экран, карточки кейсов и футер с контактами.
**Страница кейса** свёрстана до раздела «Введение», остальные разделы — следующий этап.
Вёрстка пока рассчитана только на десктоп (1360px) и только на русский язык —
подробнее в [границах текущего этапа](CLAUDE.md#границы-текущего-этапа).

Живой сайт: **https://tolegenaibek.vercel.app**

## Стек

- [Astro](https://astro.build) — статическая генерация, без клиентского JS на этой странице
- Manrope через встроенный в Astro Fonts API: шрифт скачивается при сборке и
  раздаётся со своего домена, запросов к Google на проде нет
- Content collections — кейсы описаны файлами в `src/content/cases/`

## Команды

```bash
npm install       # установить зависимости
npm run dev       # локальная разработка на http://localhost:4321
npm run build     # сборка в dist/
npm run preview   # посмотреть собранный сайт
npm run check     # проверка типов и шаблонов
```

Тестов в проекте нет.

## Контакты и ссылки

Имя, опыт работы и адреса кнопок собраны в `src/data/profile.ts` — правятся там,
без захода в разметку.

Резюме подключено ссылкой на Google Drive: обновляется без пересборки сайта,
но требует, чтобы файл оставался доступным по ссылке всем. Чтобы отвязаться
от Drive — положить PDF в `public/` и указать в `links.cv` путь `/cv.pdf`.

## Структура

```
src/
  styles/tokens.css   # дизайн-токены из переменных Figma: цвета, типографика, сетка
  styles/global.css   # сброс и базовая типографика
  layouts/            # каркас страницы: <head>, шапка, футер
  components/         # Header, Footer, Hero, CaseCard, Button, Badge, Icon…
                      # страница кейса: CaseHero, CaseSection, CaseTextBlock,
                      # FactCard, BulletList, PhoneShots
  icons/              # набор иконок из макета, по файлу на иконку
  content/cases/      # кейсы: по файлу на кейс
  data/profile.ts     # имя, опыт, ссылки
  data/ui.ts          # подписи интерфейса
  pages/index.astro   # главная
  pages/cases/[id].astro  # страница кейса
public/               # favicon, robots.txt, сюда же резюме
```

### Как добавить кейс

Создать файл в `src/content/cases/`, картинки положить в `src/assets/`:

```yaml
---
title: Название кейса
order: 3 # порядок на главной, меньше — выше
metrics:
  - value: +12%
    label: к конверсии
tags:
  - mobile
shots:
  - src: ../../assets/имя-файла.png
    alt: Что на экране
---
```

Карточка на главной появится сама. Поля проверяются схемой в `src/content.config.ts` —
при опечатке сборка упадёт с понятной ошибкой. Значения с двоеточием внутри
обязательно брать в кавычки, иначе YAML не разберётся.

### Как наполнить страницу кейса

Текст страницы живёт в поле `sections` того же файла — тело markdown не
используется. Раздел — это заголовок слева и блоки справа:

```yaml
titleLines: # разбивка H1 на строки, как в макете; необязательное поле
  - Первая строка
  - вторая строка
sections:
  - title: Введение
    blocks:
      - type: metrics # ряд плиток с метриками
        items:
          - value: +12%
            label: к конверсии
            tone: solid # solid — залитая зелёным, subtle — светлая (по умолчанию)
      - type: text # заголовок и абзацы
        title: О продукте
        paragraphs:
          - Первый абзац
      - type: list # заголовок и список с маркером
        title: Результат
        marker: success # success — зелёная стрелка, star — серая искра (по умолчанию)
        items:
          - +12% к конверсии
      - type: note # жёлтая плашка-подсказка с иконкой «i»
        title: Заголовок плашки
        text: Пояснение
        definition: Всплывает при наведении на заголовок # необязательное
      - type: heading # подзаголовок шага внутри раздела
        text: Название шага
      - type: slider # серый контейнер с экранами и подписями
        tone: problem # problem — красные подписи, solution — зелёные
        gapBefore: 24 # прижать к подзаголовку выше (по умолчанию 80)
        slides:
          - shots:
              - alt: Что на экране # без src на месте экрана стоит заглушка
            comments:
              - Подпись под экраном
```

Стрелки и точки у слайдера появляются сами, когда слайдов больше одного.
В слайдере изображения — только сами экраны: подписи, точки и выделения
собраны кодом, чтобы английскую версию не пришлось перерисовывать.

Пока у кейса нет ни одного раздела, страница не собирается — в адресах и
sitemap не появится пустышка. Готовая страница открывается по `/cases/имя-файла/`,
и карточка такого кейса на главной сама становится ссылкой на неё.

### Как добавить иконку

Положить SVG в `src/icons/` — имя файла без расширения и есть имя иконки:

```astro
<Icon name="send-letter" />
<Icon name="up" size={20} />   <!-- size задаёт сторону, пропорции сохраняются -->
```

Правки в `Icon.astro` не нужны. Размер по умолчанию берётся из самого файла —
он же размер иконки в макете. Одноцветные заливки (`black`, `white`) компонент
убирает, чтобы иконка наследовала цвет текста; осмысленные цвета вроде жёлтой
звезды остаются. Опечатка в имени валит сборку со списком доступных иконок.

## Деплой

Сайт живёт на [Vercel](https://vercel.com). Продакшн обновляется автоматически при
пуше в `main`; пуш в любую другую ветку даёт отдельную preview-ссылку и на прод не
влияет. Про смену домена и проверку, что деплой доехал, — в
[CLAUDE.md](CLAUDE.md#деплой).
