# Портфолио

Персональный сайт-портфолио продуктового дизайнера. Свёрстан по макету Figma
(файл `Auth Center`).

Сейчас готова **главная страница**: первый экран, карточки кейсов и футер с контактами.
Готовы и **обе страницы кейсов** — первая про мобильное приложение, вторая про веб.
У второго кейса экранов пока нет: на их месте заглушки с подписью.
Вёрстка пока рассчитана только на десктоп (1360px) и только на русский язык —
подробнее в [границах текущего этапа](CLAUDE.md#границы-текущего-этапа).

Живой сайт: **https://tolegenaibek.vercel.app**

## Стек

- [Astro](https://astro.build) — статическая генерация, без клиентского JS на этой странице
- Manrope через встроенный в Astro Fonts API: шрифт скачивается при сборке и
  раздаётся со своего домена, запросов к Google на проде нет
- Content collections — кейсы описаны файлами в `src/content/cases/`

## Команды

```bash
npm install       # установить зависимости
npm run dev       # локальная разработка на http://localhost:4321
npm run build     # сборка в dist/
npm run preview   # посмотреть собранный сайт
npm run check     # проверка типов и шаблонов
```

Тестов в проекте нет.

## Контакты и ссылки

Имя, опыт работы и адреса кнопок собраны в `src/data/profile.ts` — правятся там,
без захода в разметку.

Резюме подключено ссылкой на Google Drive: обновляется без пересборки сайта,
но требует, чтобы файл оставался доступным по ссылке всем. Чтобы отвязаться
от Drive — положить PDF в `public/` и указать в `links.cv` путь `/cv.pdf`.

### Как добавить кейс

Создать файл в `src/content/cases/`, картинки положить в `src/assets/`:

```yaml
---
title: Название кейса
order: 3 # порядок на главной, меньше — выше
metrics:
  - value: +12%
    label: к конверсии
tags:
  - mobile
shots:
  - src: ../../assets/имя-файла.png
    alt: Что на экране
---
```

Карточка на главной появится сама. Поля проверяются схемой в `src/content.config.ts` —
при опечатке сборка упадёт с понятной ошибкой. Значения с двоеточием внутри
обязательно брать в кавычки, иначе YAML не разберётся.

Картинки кладутся **PNG в двойном размере**: экран карточки 640×1386, экран
слайдера 576×1248, фото в первом экране 440×440. Astro сам пережмёт их в WebP
и соберёт `srcset` — присылать уже сжатое не надо, иначе картинка сожмётся
дважды. Экспортировать только сам экран: рамку телефона, скругление и тень
рисует вёрстка.

Имя файла экрана слайдера задаёт его место: `case-<шаг>-<problem|solution>-<слайд>-<экран>.png`,
где шаг — `documents`, `recipients` или `signing`. Порядок экранов внутри
слайда берётся из макета, а не из имён присланных файлов.

### Как наполнить страницу кейса

Текст страницы живёт в поле `sections` того же файла — тело markdown не
используется. Раздел — это заголовок слева и блоки справа:

```yaml
titleLines: # разбивка H1 на строки, как в макете; необязательное поле
  - Первая строка
  - вторая строка
sections:
  - title: Введение
    titleLines: # разбивка заголовка раздела на строки; необязательное поле
      - Введение
    blocks:
      - type: metrics # ряд плиток с метриками
        items:
        caption: Откуда числа # необязательное: строка над плитками
        items:
          - value: +12%
            label: к конверсии
            tone: solid # solid — залитая зелёным, subtle — светлая (по умолчанию)
      - type: text # заголовок и абзацы
        title: О продукте
        term: doc-types # необязательное: блок задаёт определение термина
        paragraphs:
          - Первый абзац
      - type: list # заголовок и список с маркером
        title: Результат
        # star — серая искра (по умолчанию), insight — жёлтая звезда,
        # success — зелёная стрелка и зелёный текст, done — зелёная галочка
        marker: success
        items:
          - +12% к конверсии
      - type: note # жёлтая плашка-подсказка с иконкой «i»
        title: Заголовок плашки
        text: Пояснение
        definition: Всплывает при наведении на заголовок # необязательное
      - type: heading # подзаголовок шага внутри раздела
        text: Название шага
        gapBefore: 160 # 160 — новый шаг в разделе, 80 — обычный (по умолчанию)
      - type: slider # серый контейнер с экранами и подписями
        tone: problem # problem — красные подписи, solution — зелёные
        gapBefore: 24 # прижать к подзаголовку выше (по умолчанию 80)
        device: phone # phone — ряд телефонов (по умолчанию), desktop — один браузер
        # auto (по умолчанию) — стрелки и точки появляются от двух слайдов,
        # always — держать место под них, пока экраны ещё не приехали
        controls: auto
        slides: # слайдов может быть сколько угодно
          - title: Заголовок слайда # необязательный, по центру над экранами
            shots:
              - alt: Что на экране # без src на месте экрана стоит заглушка
              - alt: Что на втором экране
            comments: # по подписи на экран — каждая под своим
              - Подпись под первым
              - "" # пустая строка — место есть, плашки нет
          - shots:
              - alt: Экран следующего слайда
              - alt: И второй его экран
            comments: # одна подпись при нескольких экранах — на весь ряд
              - Подпись про оба экрана сразу
```

Подписей либо столько же, сколько экранов — тогда каждая стоит под своим
(пустая строка оставляет пустое место), — либо одна: тогда она растягивается
на весь ряд и выключается по центру, как подпись ко всему шагу. Обе раскладки
есть в макете. Заголовок принадлежит слайду и листается вместе с ним.

### Термины с подсказкой

Слово в тексте помечается `[[ключ|слово в тексте]]`, а определение задаёт
текстовый блок с тем же ключом в поле `term` — обычно в разделе
«Терминология». Работает и в абзацах, и в строках списков:

```yaml
      - type: text
        title: Типы документа
        term: doc-types
        paragraphs:
          - Преднастроенные шаблоны документов…
      - type: list
        title: Анализ
        items:
          - Пользователей путает множество [[doc-types|типов документов]]
```

Если ключ совпадает с самим словом, хватает `[[слово]]`. Термин без
определения остаётся подчёркнутым, но подсказки не показывает. Строку,
которая начинается с `[[`, YAML требует брать в кавычки.

Стрелки и точки появляются сами, когда слайдов больше одного, — дописывать
ничего не нужно. На первом и последнем слайде стрелка в тупиковую сторону
выключается. Высоту дорожки задаёт самый высокий слайд, поэтому при листании
контейнер не дёргается. Экранов в слайде может быть и меньше трёх — ряд
останется по центру.

Листать можно стрелками и точками, перетаскиванием мышью, горизонтальным
жестом тачпада и стрелками на клавиатуре — слайдер всегда доезжает до
ближайшего слайда. Подробности — в
[CLAUDE.md](CLAUDE.md#как-листается-слайдер).

В слайдере изображения — только сами экраны и выноски (кривые линии между
ними, SVG из макета — текста в них нет): подписи, точки и выделения собраны
кодом, чтобы английскую версию не пришлось перерисовывать. Выноски и овалы
задаются полями `connectors` и `highlights` слайда — координаты из макета,
от левого верхнего угла ряда экранов (пример — в `documents-flow.md`).
Если в макете выноска отражена, отражение вписывается в сам SVG — подробности
в [CLAUDE.md](CLAUDE.md#решения-которых-в-макете-нет).

### Кейс про веб

У кейса про веб мокап другой: `device: desktop` ставит в слайдер один экран
1008×630 в рамке браузера вместо ряда телефонов, а поле `cover` (экран
1104×632 в сером контейнере) заменяет `shots` — и в первом экране страницы,
и в карточке кейса на главной.

Подписи там лежат **поверх** экрана, а не под ним, — места под ним нет.
Поэтому вместо `comments` слайд получает `callouts`, где у каждой плашки
свои координаты и ширина, снятые с макета:

```yaml
cover:
  alt: Что на экране первого экрана кейса # без src — заглушка

      - type: slider
        device: desktop
        tone: problem
        slides:
          - title: Заголовок слайда # необязательный
            shots:
              - alt: Что на экране
            callouts:
              - text: Подпись, которая лежит на экране
                x: 676 # от левого верхнего угла экрана, как в макете
                y: 281
                width: 308 # высоту плашка берёт по тексту
                align: center # необязательное: выключка по центру
```

Заголовок раздела при этом можно не задавать вовсе: раздел без `title`
считается продолжением предыдущего — левая колонка у него пустая, а его шаги
оглавление дописывает в главу выше. Так в макете набран второй шаг «Решений»
второго кейса.

Пока у кейса нет ни одного раздела, страница не собирается — в адресах и
sitemap не появится пустышка. Готовая страница открывается по `/cases/имя-файла/`,
и карточка такого кейса на главной сама становится ссылкой на неё.

У страницы кейса есть плавающее оглавление «Навигация по кейсу» — колонка
линий у левого края окна, по линии на раздел и шаг. Текущая глава подписана
текстом, при наведении линии превращаются в названия, клик ведёт к главе.
Собирается само из заголовков разделов и шагов; каждый раздел заодно получает
якорь латиницей (`/cases/…/#vvedenie`) — ссылкой можно делиться. Оглавление
видно на окнах шире 1780px, на узких спрятано, чтобы не ложиться на текст.
Устройство и причины решений — в [CLAUDE.md](CLAUDE.md#оглавление-кейса-навигация-по-кейсу).

Заголовок вкладки и описание для поисковиков и превью ссылок правятся без
захода в разметку: имя — в `src/data/profile.ts` (`name`), описание — там же
(`description`).

### Как добавить иконку

Положить SVG в `src/icons/` — имя файла без расширения и есть имя иконки:

```astro
<Icon name="send-letter" />
<Icon name="up" size={20} />   <!-- size задаёт сторону, пропорции сохраняются -->
```

Правки в `Icon.astro` не нужны. Размер по умолчанию берётся из самого файла —
он же размер иконки в макете. Одноцветные заливки (`black`, `white`) компонент
убирает, чтобы иконка наследовала цвет текста; осмысленные цвета вроде жёлтой
звезды остаются. Опечатка в имени валит сборку со списком доступных иконок.

## Деплой

Сайт живёт на [Vercel](https://vercel.com). Продакшн обновляется автоматически при
пуше в `main`; пуш в любую другую ветку даёт отдельную preview-ссылку и на прод не
влияет. Про смену домена и проверку, что деплой доехал, — в
[CLAUDE.md](CLAUDE.md#деплой).
